# The langchain stack stays on the 0.3 / langgraph 0.6 line, and these pins are
# mutually load-bearing — `langchain` (needed by langfuse.langchain, below)
# requires langchain-core>=1.0 from its 1.0 release onward, so pinning
# langchain>=1.0 while holding langchain-core<1.0 is unsatisfiable. That exact
# contradiction shipped on 2026-08-06: `pip install -r` died with
# ResolutionImpossible, which reddened CI's agents job and broke the Cloud Build
# of the agents image, so nothing shipped until it was fixed.
#
# The 1.x line does work — the app imports and langfuse loads under it — so
# moving is a real option, but move ALL of these together and re-verify the
# provider adapters: langchain-anthropic 0.3.x explicitly forbids
# langchain-core 1.x, and a mixed set installs happily while `pip check` fails.
#
# Floors are >=0.3, not >=0.2: the 0.2-era adapters need langchain-core<0.3, and
# leaving them reachable makes pip backtrack through them for minutes before it
# gives up. scripts/agents/deps-check.mjs resolves this file in the real base
# image and asserts the versions that come out.

# D.0.7 — LLM observability. CallbackHandler integrates with LangChain 0.3
# and captures prompts, tool calls, token counts, latency, cost per trace.
#
# This range spans TWO incompatible handler designs and app/tracing.py
# implements both — see its module docstring before changing the bounds:
#   v2  langfuse.callback.CallbackHandler, auth + trace attrs on the constructor
#   v3+ langfuse.langchain.CallbackHandler, auth on a client singleton and
#       trace attrs in the LangChain run config
# A fresh install resolves to v4. Fixing only the import path is not enough:
# the v2 constructor kwargs raise TypeError against a v4 handler, which
# get_callback() swallows, so tracing goes silently dark everywhere while
# tracing_enabled() still reports True. scripts/smoke_langfuse_live.py is the
# check that actually catches this — it sends a trace and reads it back.
