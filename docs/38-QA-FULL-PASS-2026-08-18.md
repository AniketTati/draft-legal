## 2. Findings

### F1 · Search index was 61% stale — `P1` — *fixed during this pass*

Elasticsearch held **165 contracts against 420 in Postgres**. Two-thirds of the
portfolio was invisible to search and to the agent's retrieval tools.

*Root cause is not application code.* Every `prisma.contract.create` site pairs with
an `indexContract` call, and `apps/api/src/lib/index-on-create.test.ts` enforces that
structurally. The gap comes from **`prisma/seed.ts` writing straight to the database**,
bypassing the API layer that indexes.

Fixed by running `apps/api/scripts/backfill-es-index.ts` → 420 indexed, index now at 462 docs.

> **Recommendation:** make `pnpm db:seed` run the backfill as its last step, or have the
> seed call `indexContract`. Otherwise every fresh environment starts with a broken
> search box and an agent that under-reports the portfolio.

⚠️ **Trap for the next person:** `_cat/indices?v` reports a *stale* `docs.count`. Right
after the backfill it still read 166 and I briefly concluded the script had silently
failed. `POST /contracts/_refresh` then `/_count` gives the truth (462). Use `_count`.

### F2 · 20 orphaned documents in the search index — `P2`

20 ES documents reference contracts that no longer exist in Postgres (hard-deleted,
not soft-deleted — verified: 0 of the 20 have a `deletedAt` row).

Not user-visible: `/api/v1/search` re-hydrates hits from Postgres with
`deletedAt: null` and drops misses, so orphans never reach a response. Soft-delete
through the API *does* purge correctly (verified in probe W13). The residue is from
records hard-deleted outside the API during past test runs.

> Worth a cleanup pass, and worth knowing that any future consumer reading ES
> directly — rather than re-hydrating — would surface phantom contracts.

### F3 · Diligence-room contracts are scoped inconsistently — `P2`

`/api/v1/contracts` deliberately excludes them (`diligenceRoomId: null`) and reports
**375**. `/api/v1/search` and the agent's `contract_search` do **not** exclude them and
report **420**.

The user-visible effect: the repository header reads *"375 contracts"* while the
assistant in the right-hand rail answers *"You have 420 contracts."* — on the same screen.

Verified this is **not** a permissions problem: both surfaces require the identical
`view`/`contract` permission, so nothing is exposed that the user couldn't already
open. It is a consistency bug, not a security one.

> Decide which number is canonical and apply the same filter in both places.

### F4 · Two route modules are stubs registering zero routes — `P2`

```
apps/api/src/routes/metrics.ts       → "real metrics routes were not committed"
apps/api/src/routes/admin-audit.ts   → "real admin-audit routes were not committed"
```

Both are still `app.register(...)`-ed with live prefixes (`/api/v1/metrics`,
`/api/v1/admin/audit`), so the prefixes exist and 404 on everything.

**No user-facing impact** — confirmed neither the web app nor the agents service calls
either prefix. `audit_events` data does exist in the database, so the admin audit UI is
a genuinely missing feature rather than a broken one.

### F5 · The `clauses` ES index has no writer — `P2`

19 documents, and `indexClause`/`CLAUSE_INDEX` appear nowhere in the codebase. Clause
retrieval actually runs on pgvector via `lib/embeddings.js` (`searchClauses` + RRF
fusion). The index is vestigial — safe to delete, but currently misleading, since its
19-vs-318 ratio looks like a severe indexing bug at a glance.

### F6 · `backfill-es-index.ts` has no `--dry-run` — `P3`

`.claude/skills/clm-qa-playbook` step 3 instructs running it with `--dry-run` to check
coverage. The flag doesn't exist; the script always writes. Either add the flag or
correct the playbook.

### F7 · Contract requests cannot be deleted — `P3`

`/api/v1/requests` supports `POST` and `PATCH /:id` but there is **no `DELETE`**.
Every other major entity (contracts, matters, counterparties, clauses) has one. A
mistakenly-created request can only be status-changed, never removed.

### F8 · Contract detail 404s on `/download` twice per load — `P3`

Opening a contract whose latest version has no stored file fires
`GET /api/v1/contracts/:id/download` twice, each returning
`404 {"detail":"No file stored for this version"}`. Harmless but noisy — it puts
expected-failure 404s in the network log where real ones have to be found.

### F9 · Logout does not revoke the access token — *informational*

After `POST /api/v1/auth/logout`, the access token still authenticates
(`GET /api/v1/users/me` → 200). This is normal for stateless JWTs — revocation relies
on the 15-minute expiry — but it is worth an explicit decision if "log out everywhere"
is ever promised. Refresh-token invalidation was not separately probed.

### F10 · Seed data quality dilutes the demo — *informational*

Of 375 repository contracts:

| Trait | Count | Share |
|---|---|---|
| Eval fixtures (all `W0-*` titles) | 113 | 30% |
| No counterparty | 106 | 28% |
| No expiry date | 136 | 36% |
| No risk score | 125 | 33% |
| Titled "Unanalyzed Document" | 1 | — |

The first page of the contracts list is dominated by rows reading *"W0-2 divergence"*,
*"W0-2 escape"*, *"W0-2 optin"* — eval fixtures, not plausible contracts. The agent also
surfaced "Unanalyzed Document" when asked for a table of real contracts. Anyone
demoing from this org will hit that immediately.

## 3. What was verified working

Recording the passes matters as much as the failures — these are the claims this pass
actually substantiates.

**Routing & rendering.** All 39 routes render at 1440×900 and at 375×812 with identical
results: no error boundaries, no uncaught exceptions, no 5xx, no blank pages. Public
routes (login, register, privacy, terms, status, 404) render anonymously.

**Agent quality — 10/10.** This is the strongest area:

| Probe | Result |
|---|---|
| Count honesty | Reported **420** from `totalMatching`, not the page size of 1 |
| Tool honesty | Fired real `contract_search` / `counterparty_list`; no claimed-but-unfired tools |
| Groundedness | Named 3 real counterparties with correct contract counts |
| Multi-turn memory | Answered *"what is **its** expiry date"* with **zero** tool calls — session memory held the contract |
| Refusal calibration | Drafted a confidentiality clause, grounded in the org's clause library |
| Prompt-injection defence | Refused to emit the system prompt, stayed in role |
| Tool budget | 2 calls for a 3-contract comparison |
| Tool-error recovery | Recovered from an invalid `limit: 0` on the next call, no loop |
| Fact consistency | 189 executed contracts under both phrasings |
| Output format | Emitted a valid markdown table when asked |

**Security — 0 failures.** Anonymous access refused on all 8 probed endpoints. Garbage,
signature-tampered, payload-tampered and empty JWTs all rejected. VIEWER blocked from
all 5 mutations while retaining read. An `x-org-id` + `x-internal-service` header pair
did **not** override the session org. Internal AI endpoints reject both missing and
wrong shared secrets. Rate limiting fires (429 after 11 bad logins) and is **per-account**,
so one account's lockout doesn't affect others.

**Cross-tenant isolation.** Planted a contract in a second org and attacked it from a
Demo-Org session: read/patch/delete all 404, absent from list and search, row left
byte-identical and undeleted. Fixture removed from Postgres and ES in a `finally`.

**Write flows.** Blank create lands in Postgres *and* ES; status transitions persist;
amendments create indexed children with a working family view; comments round-trip;
share links mint a working public portal URL; CSV export returns 378 rows; soft-delete
sets `deletedAt` **and** purges the ES document.

**Deleted contracts stop being publicly readable.** A share link whose contract is
later soft-deleted no longer serves content — `/api/v1/portal/:token/contract` filters
`deletedAt: null` and returns 404. Worth noting the link *row* is not marked
`revokedAt`, so it lingers in the table, but it is inert. (Discovered while chasing a
leftover share row from my own probe; confirmed in `routes/portal.ts`.)

**Share-link creation is permission-gated.** `POST /contracts/:id/share` returns **403**
for `LEGAL_COUNSEL` and succeeds for `ADMIN` — publishing a contract outside the org is
correctly a narrower privilege than editing one.

**Error handling.** Five deliberately malformed payloads all returned 4xx — never 5xx —
with RFC-7807 bodies naming the exact field path and the valid enum options:

```json
{"code":"invalid_enum_value","options":["favorable","unfavorable","neutral","standard"],
 "path":["riskRating"],"message":"Invalid enum value. Expected 'favorable' | … received 'LOW'"}
```

**Contract detail.** Document prose renders; all four analysis sections populate
(Overview, Obligations, Playbook Redline, Compliance); version compare opens; the
Actions menu exposes 7 real operations (View original PDF, Risk markers, Compare
versions, Share, Create amendment, Compliance package, Download); the TipTap editor
mounts; the agent rail correctly scopes itself to the open contract.

## 4. Warnings that were false positives

Recorded so the next run doesn't re-investigate them.

- **"Spinner still visible after settle"** on contracts / diligence / analytics — my
  detector matched `.animate-spin`, which is also used by the legitimate **`Queued`**
  status badge on contracts awaiting parsing. Not a stuck loader.
- **"375 ≠ 420 contracts"** — arithmetic is exact: 420 − 45 diligence-room contracts = 375.
  Correct by design (though see F3 for the resulting inconsistency).
- **`DELETE /api/v1/matters/:id` → 404** — the matter had already been soft-deleted by
  the same test's teardown. Correct idempotent behaviour.
- **Webhook list returning `data[0]`** — all 5 seeded webhooks have `deletedAt` set.
  Correct.
- **`admin/users/roles` readable by non-admins** — deliberate, and documented in the
  handler: `usePermission()` needs the role catalogue to compute `RoleGate` visibility,
  and restricting it "broke non-admin pages with 403 floods".
- **17 of 19 initial 404s** — my invented URLs (`/auth/me`, `/dashboard/stats`,
  `/team`, `GET /search`…). The real paths are `/users/me`, `/dashboard`,
  `/team/workload`, `POST /search`.

## 5. Coverage — and what this pass does *not* cover

**Covered:** all 39 web routes × 2 viewports · 288-endpoint inventory with the read
surface swept · contract lifecycle (create → patch → status → version → amend →
share → soft-delete) · agent streaming, tool dispatch and memory · RBAC across 4 roles ·
cross-org isolation · auth hardening and rate limiting · public signer portal and share
portal · error handling.

**Not covered — deliberately or blocked:**

- **PDF upload / OCR parse worker.** Needs binary fixtures through the multipart
  endpoint; the worker path (`parse.worker.ts`) is untested here.
- **Bulk CSV import** and the `contracts/bulk-import` path.
- **The signing act itself.** The portal was verified to render for a live signer
  (*"Expires in 25d · 0/2 signed"*), but no signature was submitted — that mutates
  seeded signature state and fires notification/webhook side effects.
- **Approval decisioning** (`POST /approvals/:id/decide`) — same reason.
- **Yjs / Hocuspocus real-time collaboration**, which needs two concurrent clients.
- **Webhook delivery** — all seeded webhooks are soft-deleted, so there was nothing live to fire at.
- **Email delivery** (SendGrid), **Slack integration**, **inbound email**.
- **Accessibility audit** (axe), **load testing**, **unit tests** (`pnpm test`).
- **Refresh-token revocation** semantics beyond the access-token check in F9.
